# TabDDPM's tuned configuration vs the GNN configuration actually run

_Generated by `config_comparison.py`; read-only (nothing trained or sampled; both denoisers are only instantiated, untrained, on CPU to count parameters). Every value carries the file:line it was read from._

**Caveat.** TabDDPM's configurations were tuned per dataset with Optuna on the validation split (architecture *and* lr, steps, batch size, synthetic size, …). Mine come from a grid over GNN architecture only, selected on the test split (development datasets), or were transferred from other datasets (held-out); the training hyperparameters are not tuned per dataset at all. Differences in results below therefore confound architecture with training budget and tuning effort.

### house

house is numerical-only (16 features + y as a numerical node = 17 nodes), so the categorical-input fix does not touch it. My runs are below TabDDPM's own result by fixed -0.080, Jenks -0.044, entmax-1.5 -0.037 R² (TabDDPM 0.6766). The largest configuration differences there: **30,000 → 20,000 steps** (0.67×), **lr 1.39e-03 → 1e-04** (0.07×, the smallest ratio among held-out datasets with results: king 0.13×, cardio 0.18×, default 0.21×; without results: fb-comments 0.16×, higgs-small 0.10×, miniboone 0.04×), and a denoiser 1.27× TabDDPM's size (1,325,969 vs 1,041,553). Batch size (4096), synthetic size, normalization, diffusion and evaluation settings are the same (as everywhere, mine samples the EMA weights and TabDDPM the raw ones); both sides decay the lr linearly to 0, so steps × initial lr is 0.05× TabDDPM's. With n = 1 dataset this is a description, not a diagnosis.

## Caveats

- TabDDPM tuned per dataset on validation (Optuna); mine: architecture grid (development, selected on test) or transfer (held-out), training hyperparameters untuned. See the caveat at the top.
- The TabDDPM numbers are the authors' `eval_catboost.json` shipped in `exp/<ds>/ddpm_cb_best/` (the paper's Table 5 rounds them to 3 decimals); not re-run here.
- The two sides sample different checkpoints: TabDDPM's `eval_seeds.py` copies `model.pt` (raw weights), the runner samples `model_ema.pt`.
- My configuration values are read from the code as it is now; the runs record no git commit (`git_commit: unknown`). Checked with git: the assignments of `ABLATION_LR`, `ABLATION_STEPS`, `ABLATION_BATCH_SIZE` last changed in 220838d (2026-06-11), the earliest run here started 2026-09-24, and the uncommitted diff of `ablation_runner.py` does not touch them. One exception is recorded: fb-comments' `sample_batch_size` (150 000 → 50 000, commit 385a768), which changes only how sampling is batched.
- Parameter counts are for the denoiser only; the diffusion wrapper has no trainable parameters.
- **default: the local data is not the dataset the authors' config was tuned and evaluated on.** Their `info.json`: 20 numerical + 3 categorical, val/test 4800/6000; local `data/default/`: 14 + 9, val/test 6000/4800 (`num_numerical_features` 20 → 14 in commit 385a768 to match the local data). Its TabDDPM parameter count here uses the LOCAL shapes, and its Δ vs TabDDPM (here and in the paper comparison) is not like-for-like: the test set and the column typing differ.
