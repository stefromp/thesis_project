## Which files are original scale

Synthetic samples are read from `gen_seed_<k>/X_num_train.npy`, `X_cat_train.npy`, `y_train.npy`; `X_*_unnorm.npy` are never used.

- `scripts/sample.py:146` — categoricals are inverse-transformed to their original labels
- `scripts/sample.py:150` — `X_num_unnorm` is saved BEFORE the inverse transform (model space)
- `scripts/sample.py:151` — numericals are inverse-transformed to original scale
- `scripts/sample.py:162` — regression without y-conditioning: y is column 0 of the inverse-transformed numericals
- `scripts/sample.py:165` — numericals that are discrete in the real data are rounded to real values
- `scripts/sample.py:169` — saved as `X_num_train`
- `scripts/sample.py:171` — saved as `X_cat_train`
- `scripts/sample.py:172` — saved as `y_train`
- `ablation/ablation_runner.py:506` — the ablation runner uses exactly this function

The runner does not pass `disbalance`, so labels are drawn from the empirical class distribution and synthetic label frequencies are comparable with real ones.

## Protocol

- Reference = real **train** split (what the model learned from), all rows, capped at 100,000 by a seeded subsample. Compared set = n_cmp = min(n_test, 20,000) rows.
- Floor = real **test** vs real train at the same n_cmp: the best a generator can realistically reach, since an independent real sample of that size scores this.
- Synthetic: a seeded subsample (seed 0) of n_cmp rows per gen seed, identical indices for every rule. Synthetic sets are 1–8× the real train size, so no gen seed is used in full.
- Column types come from `data/<ds>/info.json`. The target is a column: categorical for classification, numerical for regression.
- Association matrix: Pearson (num–num), correlation ratio (cat–num), Theil's U (cat–cat, asymmetric U(row|col)), implemented here after dython's definitions (dython is not installed). Undefined entries (e.g. a constant synthetic column) are not filled: the distance is then left undefined.
- **Column Pair Trends is computed pair by pair, not taken from QualityReport.** sdmetrics 0.28.1 (installed) differs from the 0.13.0 the repo pins for the TabDiff suite in two ways that break the report value: (1) QualityReport averages only pairs whose real correlation > 0.5 / association > 0.3 (4 of 66 pairs on cardio); (2) its Pair Trends property bins numerical columns on each table's own range (`column_pair_trends.py:297-298`, `bin_edges=None`), so a bin means different values in real and synthetic whenever their ranges differ. Here: all pairs; Pearson `CorrelationSimilarity` for num–num; `ContingencySimilarity` otherwise, with numerical columns binned on the real column's edges (`sdmetrics.utils.discretize_column`, 10 equal-width bins). The QualityReport value (all pairs, per-table bins) is kept as `column_pair_trends_qr` for reference; on cardio it puts real test vs real train at 0.73 against 0.99 with shared bins. Column Shapes is taken from QualityReport (KS / TV complement; no binning involved).
- **This Pair Trends is a custom version (all pairs, bins shared from the real column). It is not comparable with the "Trend" numbers reported in the TabDiff paper**, which come from SDMetrics' own report; compare rules with each other and with the real-real floor only.
- Relative to floor: distance ÷ floor distance; for SDMetrics, (1 − score) ÷ (1 − floor score). 1 = as good as an independent real sample; larger = worse.

## Categorical-input bug

**Cause.** `GraphAwareDenoiser` embedded each categorical column from the diffusion's *log* one-hot (`tab_ddpm/utils.py:133`, `log(one_hot.clamp(min=1e-30))`, so empty classes are ≈ −69) through its own `Linear(K, d_model)` (`tab_ddpm/graph_denoiser.py`, the categorical input projection), with no normalisation. With K = 2–5 the initial weights are large, and the categorical node embedding dwarfs the timestep embedding added to it: those nodes barely see t. Some categorical columns then learn to copy their noisy input x_t instead of predicting x_0; the reverse chain stays near its uniform starting draw. The original TabDDPM MLP gets the same input through one shared `Linear(d_in, 128)` (`tab_ddpm/modules.py:444,459`) and did not show the failure in the toy test.

**Fix.** `GraphAwareDenoiser(cat_input="prob")` feeds `exp()` of that slice, the one-hot probabilities. `cat_input="log"` (default) is bit-identical to the code before the option (tests/test_cat_input.py, against 3b8b8b3), so existing checkpoints and split jobs are unaffected. Fixed runs go to `*_catfix` trees; `split_runner --load_checkpoint` refuses a checkpoint trained with the other setting (`denoiser_config.json`, absent = "log").

## Caveats

- **The floor is not a strict bound.** A model fit to the train split can reproduce train-specific structure more closely than an independent real sample does, so a rule can score better than real test vs real train. Cells better than the floor: SDMetrics Column Pair Trends 21/39 (buddy/entmax15, buddy/fixed, buddy/jenks, california/entmax15, california/fixed, cardio/entmax15, cardio/fixed, cardio/jenks, churn2/entmax15, churn2/fixed, churn2/jenks, gesture/entmax15, gesture/fixed, gesture/jenks, house/entmax15, house/fixed, house/jenks, insurance/entmax15, insurance/jenks, wilt/entmax15, wilt/jenks); association distance, mean |Δ| per pair 21/39 (buddy/entmax15, buddy/fixed, buddy/jenks, california/entmax15, california/fixed, cardio/entmax15, cardio/fixed, cardio/jenks, churn2/entmax15, churn2/fixed, churn2/jenks, gesture/entmax15, gesture/fixed, gesture/jenks, house/entmax15, house/fixed, house/jenks, insurance/entmax15, insurance/fixed, insurance/jenks, wilt/entmax15); SDMetrics Column Shapes 12/39 (buddy/entmax15, buddy/fixed, buddy/jenks, churn2/entmax15, churn2/fixed, churn2/jenks, diabetes/entmax15, diabetes/jenks, house/entmax15, wilt/entmax15, wilt/fixed, wilt/jenks). Read `rel_to_floor` < 1 as "within real sampling noise of train", not as better than real data.
- **n per subset** (datasets with at least one rule computed): held-out 4, development 9. Held-out cells complete for all three rules: cardio, default, house, king.
- **Missing or corrupt:** fb-comments/fixed (missing); fb-comments/jenks (missing); fb-comments/entmax15 (missing).
- **Sub-sampling:** every synthetic gen seed is sub-sampled to n_cmp rows (column in the tables); real train is used in full up to 100,000 rows. The seed-to-seed sd therefore mixes generator variability with sub-sampling noise at that n.
- **n = 5 gen seeds of one trained model per cell**: training-seed variance is not in any sd.
